# ADR-0004: Write diagrams as Mermaid in Markdown

- **Status:** accepted
- **Date:** 2026-11-09
- **Origin:** foundation decision inherited from [sdd-template-for-claude](https://github.com/belaboros/sdd-template-for-claude)

## Context
`architecture.md` needs a context diagram, a component diagram and a coupling diagram. The diagrams must stay in sync with the code, be reviewable in pull requests, and be editable or generated by Claude and by scripts.

## Decision
We will write all architecture diagrams as Mermaid code blocks inside the Markdown files. We use a `flowchart` styled after the C4 model's context and container/component levels, rather than Mermaid's experimental `C4Context` syntax. The coupling diagram is generated into a marked block (`<!-- coupling:begin -->` … `<!-- coupling:end -->`) from the metrics snapshot.

## Alternatives considered
| Option | Why not chosen |
|--------|----------------|
| PlantUML / Structurizr | Needs a renderer or server; GitHub doesn't render it inline |
| draw.io / Excalidraw / images | Binary or opaque diffs; can't be generated from metrics |
| Mermaid `C4Context` | Experimental, with poor layout control |

## Consequences
- **Positive:** diagrams render on GitHub and in VS Code, diffs are readable, and they can be generated.
- **Negative:** less control over layout for large graphs; components may need grouping with subgraphs.
- **Follow-up:** none.
